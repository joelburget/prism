# Query engine with NULL and left outer joins — Prism

Prism 0.18.0 with its standard library and native toolchain. Run `./build.sh` once to compile `.build/query-null`; subsequent requests use the compiled executable.

Run `./run.sh`. It reads one protocol-v1 `query-null` JSON request from stdin and writes one JSON response. Every request starts a fresh process. Domain errors exit zero and contain only the fixed error code. No SQL library or external query engine is used.

The modules separate wire validation and models, SQL tokenization/parsing, binding and type checking, and execution/optimization. Binding resolves columns to flattened row slots and verifies all expressions before evaluating rows, including unreachable expressions and empty tables. The logical plan carries typed expressions, input tables, scan predicates, join kinds, and ordering.

Values are JSON, so SQL NULL is `JNull` and UNKNOWN is simply a NULL-valued boolean; `truth` is false for both FALSE and UNKNOWN, which is exactly what WHERE, ON, and HAVING require. AND and OR are evaluated from the full three-valued tables rather than from host booleans, and every other operator propagates NULL. Binding gives each expression a static type plus a conservative `nullable` flag; an untyped NULL literal carries the type `null` and unifies with whatever its context demands. A column reached through a LEFT JOIN is nullable whatever its schema declares, so outer-join padding is visible to the type-level reasoning, not only at run time.

Optimization performs bottom-up folding of constant scalar expressions and pushes single-source WHERE conjuncts into input scans. Three things keep that sound under NULL. Folding runs the same evaluator, so `NOT NULL` folds to NULL rather than to a boolean. The algebraic rewrites (`x = x`, `p OR NOT p`, `x IS NULL` on a known-present value) fire only when the `nullable` flag proves the operand cannot be NULL, which excludes nullable columns and every outer-joined source. Pushdown targets only inputs whose rows can never be NULL-padded, namely the first source and inner-joined ones; a conjunct over a LEFT JOIN's right side stays above the join, where a padded row can still be discarded. Conjuncts referencing multiple sources also remain above the join. Stable nested-loop joins, encounter-ordered groups, first-occurrence DISTINCT, stable sorting, and pagination preserve the documented ordering in either mode.

Supported surface: SELECT/WHERE, inner and LEFT [OUTER] joins, nullable schemas, NULL literals, IS NULL / IS NOT NULL, COALESCE, grouped and global COUNT/SUM/MIN/MAX, GROUP BY/HAVING, DISTINCT, ORDER BY with explicit NULLS FIRST/LAST, and LIMIT/OFFSET.

Validation: all 21 public baseline and 34 public extension cases pass. `python3 tests.py` adds hand-computed cases beyond that corpus and re-runs each successful query in both optimizer modes. This directory is self-contained; `starter.json` lists its export files. Build outputs and dependency installations are ignored.
